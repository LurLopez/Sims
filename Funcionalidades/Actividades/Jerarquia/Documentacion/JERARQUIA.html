Jerarquía de Actividades

Sistema de prioridades que controla qué puede coexistir o reemplazarse en la matriz del jugador. Tres niveles: Examen (3) > Trabajo (2) > Actividades normales (1). Garantiza que compromisos importantes nunca sean borrados accidentalmente.

Los tres niveles

3
Examen universitario
Verificación dinámica vía Carrera_Actual.
No ocupa celda en la matriz.
2
Trabajo

Comida Rápida, Carpintero, Científico…
1
Actividades normales

Dormir, Comer, Estudiar…

Flujo de ejecución

1
El jugador elige una actividad y un horario en el reloj.
Script_Principal.Crear_Actividad("Salir_A_Correr")
2
Se calcula el rango de celdas.
Actividades._Calcular_Rango(...) devuelve un Array de pares [i, j].
3
Pre-scan (solo para P1).
Se recorre todo el rango buscando celdas con prioridad > 1. Si se encuentra alguna, se devuelve false sin escribir nada. No hay escrituras parciales.
4
Escritura celda a celda.
Crear_Actividad(i, j, actividad): consulta _Prioridad_Celda, escribe solo si la prioridad existente ≤ la nueva.
5
Resultado en la GUI.
Si ok == true → Actividad_Terminada() cierra el reloj.
Si ok == false → _Mostrar_Error_Prioridad() muestra AcceptDialog; el reloj permanece abierto.

Detección del examen (P3)

⚠️ El examen no ocupa ninguna celda de la matriz. Su prioridad se evalúa en tiempo real comparando i % 7 con carrera.hora_examen_dia y j con el rango [hora_examen_inicio, hora_examen_inicio + 60). 
func _Prioridad_Celda(celda, i: int, j: int) -> int:
    var carrera = Variables_Dinamicas.Carrera_Actual
    if carrera != null and carrera.hora_examen_dia >= 0 and (carrera.matriculado or carrera.prematriculado):
        if i % 7 == carrera.hora_examen_dia and j >= carrera.hora_examen_inicio and j < carrera.hora_examen_inicio + 60:
            return 3   # CRÍTICO: no importa lo que haya en la celda
    if celda is Actividad:
        return celda.Obtener_Prioridad()
    return 0

Notas técnicas críticas

Sin escritura parcial para P1: el pre-scan recorre todo el rango antes de escribir. Si hay conflicto en la última celda, ninguna celda anterior se habrá modificado.
Obtener_Prioridad() en lugar de var prioridad: en GDScript 4, redeclarar una variable con el mismo nombre en una subclase puede no tener dispatch dinámico fiable cuando se accede mediante una referencia del tipo padre. Una función sí tiene dispatch virtual garantizado.
Trabajo no usa pre-scan: Trabajo.Trabajar() llama Actividades.Crear_Actividad(i, j, actividad) celda a celda. Las celdas de examen simplemente devuelven false y se saltan; el resto se escribe con normalidad.
