🎮 Sistema de Objetos/Muebles — Especificación de Diseño

1. Descripción General

Sistema de compra, venta y uso de muebles que afectan a las necesidades básicas del personaje mediante multiplicadores de probabilidad.

El jugador puede:

  • Comprar muebles con dinero
  • Vender muebles (excepto el básico obligatorio)
  • Seleccionar cuál usar (afecta a los cálculos de necesidades básicas)
  • Poseer múltiples del mismo tipo pero solo usar uno

2. Estructura de Clases

Clase Base: Objeto.gd

class_name Objeto extends Resource

@export var nombre: String              # ej: "Cama Premium"
@export var precio: float               # ej: 500.0

@export var es_basico: bool             # true = no se puede vender si es el único

3. Almacenamiento

Variables_Estaticas — Catálogo (inmutable, se reconstruye cada inicio)

Catalogo_Objetos = {
    "cama_basica": Objeto_Dormir(...),
    "cama_premium": Objeto_Dormir(...),
    "cama_lujo": Objeto_Dormir(...),
    "plato_basico": Objeto_Comer(...),
    # ... más objetos
}

Inicializado en Variables_Estaticas._ready() mediante _Inicializar_Catalogo_Objetos().

Variables_Dinamicas — Estado del Jugador

# Objetos que posee el jugador
Objetos_Poseidos = {
    "cama_basica": true,      # Empieza con esto
    "cama_premium": false,
    "cama_lujo": false,
    # ... etc
}

# Objeto seleccionado por categoría (afecta a cálculos)
Objeto_Seleccionado = {
    "Dormir": "cama_basica",      # String con clave del catálogo
    "Comer": "plato_basico",
    "Higiene": "espejo_basico",
    # ... etc
}

4. Flujo de Compra

  1. Jugador abre menú de tienda (UI futura)
  2. Selecciona un objeto disponible
  3. Si tiene dinero suficiente:
    • Actividades.Comprar_Objeto(clave: String)
    • Resta dinero: Variables_Dinamicas.Dinero -= precio
    • Marca como poseído: Objetos_Poseidos[clave] = true
    • Opcionalmente selecciona: Objeto_Seleccionado[categoría] = clave
    • Guarda partida

5. Flujo de Venta

⚠️ Restricción crítica: Siempre debe haber al menos un objeto de cada categoría seleccionado.
  1. Jugador selecciona objeto para vender
  2. Validación:
    • ¿Es el único de su categoría? → No se puede vender
    • ¿Es el objeto actualmente seleccionado? → Cambiar a otro primero
  3. Si es válido:
    • Actividades.Vender_Objeto(clave: String)
    • Suma dinero (ej: 50% del precio): Variables_Dinamicas.Dinero += precio * 0.5
    • Marca como no poseído: Objetos_Poseidos[clave] = false
    • Guarda partida

6. Flujo de Selección

Cambiar el objeto en uso (sin comprar/vender):

  1. Jugador selecciona nuevo objeto de su categoría
  2. Validación:
    • ¿Lo posee? → Sí → continúa
    • ¿Es diferente al actual? → Sí → continúa
  3. Si es válido:
    • Actividades.Seleccionar_Objeto(categoría: String, clave: String)
    • Actualiza: Objeto_Seleccionado[categoría] = clave
    • Guarda partida

7. Aplicación del Multiplicador

En Actividades_Necesidades_Basicas.gd, al ejecutar una actividad:

func Ejecutar_Actividad_Necesidades_Basicas_Array(efectos: Array):
    var multiplicador = _Obtener_Multiplicador(actividad_actual.nombre)
    # (resto de lógica existente * multiplicador)

func _Obtener_Multiplicador(nombre_actividad: String) -> float:
    match nombre_actividad:
        "Dormir", "Comer", "Higiene":
            var objeto_clave = Variables_Dinamicas.Objeto_Seleccionado[nombre_actividad]
            return Variables_Estaticas.Catalogo_Objetos[objeto_clave].multiplicador
        _:
            return 1.0
Ventajas de esta implementación:
  • Código limpio y centralizado con match
  • Fácil de expandir cuando se añadan nuevas categorías
  • El jugador siempre tiene un objeto seleccionado (nunca es null)
  • Acceso directo al dictionary sin validaciones innecesarias

9. Objetos Iniciales

El jugador empieza con los siguientes objetos seleccionados:

  • Cama_Basica (Dormir)
  • Mesa_Basica (Comer)
  • Ducha_Basica (Duchar)

Estos objetos no se pueden vender si son el único de su categoría, asegurando que el jugador siempre tiene al menos un objeto de cada tipo.

9. Expansión Futura

El sistema está diseñado para:

  • Añadir más objetos sin cambiar la lógica (solo expandir catálogo)
  • Crear subclases con comportamientos especiales (ej: Objeto_Dormir con efecto sleep)
  • Añadir nuevas categorías (Ocio, Trabajo, etc.)

Mejora Planeada: Objetos que Reducen Efectos Negativos

⏳ Estado: No implementado, pero planeado.

Actualmente, los multiplicadores solo aceleran efectos positivos (ej: cama premium acelera descanso). Se planea expandir para permitir objetos que reduzcan efectos negativos:

Ejemplo: Ropa de calidad (multiplicador 0.95 en Higiene):

  • Normal: cada ~20 minutos hay 1/20 prob. de perder higiene
  • Con ropa: 1/(20 × 0.95) = 1/19 prob. (caída más lenta)

Cambio necesario en Actividades_Necesidades_Basicas.gd:

if multiplicador != 1.0:
    if por_cuanto > 0:  # Efectos positivos: acelera
        valor_maximo = max(1, floor(valor_maximo / multiplicador))
    else:  # Efectos negativos: desacelera
        valor_maximo = floor(valor_maximo * multiplicador)

Nuevos objetos necesarios:

  • Objeto_Higiene.gd — ropa, jabón premium, etc. (multiplicador < 1.0)
  • Expandir catálogo con objetos tipo Ropa_Premium con multiplicador = 0.95

12. Cómo Expandir el Catálogo

Añadir un nuevo objeto (ejemplo: Cama Súper Premium)

# En Variables_Estaticas._Inicializar_Catalogo_Objetos()

var cama_super = Objeto_Dormir.new()
cama_super.nombre = "Cama_Super_Premium"
cama_super.precio = 1500.0
cama_super.multiplicador = 1.15  # +15%
cama_super.afecta_a = "Dormir"
cama_super.es_basico = false
Catalogo_Objetos["Cama_Super_Premium"] = cama_super

Crear una nueva categoría (ejemplo: Ropa para reducir caída de higiene)

  1. Crear archivo Scripts/Logica/Escena_Principal/Economia/Herencia/Objeto_Higiene.gd: 
    class_name Objeto_Higiene
extends Objeto
  2. Añadir objetos en el catálogo: 
    var ropa_premium = Objeto_Higiene.new()
ropa_premium.nombre = "Ropa_Premium"
ropa_premium.precio = 150.0
ropa_premium.multiplicador = 0.95  # Reduce caída en 5%
ropa_premium.afecta_a = "Duchar"
ropa_premium.es_basico = false
Catalogo_Objetos["Ropa_Premium"] = ropa_premium
  3. Actualizar lógica de multiplicadores en Actividades_Necesidades_Basicas.gd para soportar multiplicadores < 1.0 (ver sección "Mejora Planeada")

Consideraciones al expandir

  • Balance económico: Objetos más caros deben tener mejores multiplicadores
  • Precio de reventa: Automáticamente 50% (no es configurable por objeto)
  • Restricción de venta: No se puede vender si es único o está seleccionado
  • Recomendación de nombres: Usar PascalCase con guiones bajos (ej: Cama_Super_Premium)
