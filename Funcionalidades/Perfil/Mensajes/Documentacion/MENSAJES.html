📬 Sistema de Mensajes / Notificaciones

Versión: 1.0 | Fecha: 2026-06-10

📋 Descripción General

Sistema de notificaciones dentro del juego (no push) que almacena mensajes de eventos. Accesible desde un botón "Perfil" en la barra inferior.

Objetivo: Informar al jugador de eventos importantes sin interrumpir (trabajos cancelados, cambios de estado, etc.)

⚠️ CRÍTICO: Timestamp de evento vs. ejecución

Si cierras el juego lunes 12:00 y lo abres martes 12:00:

  • El sistema procesa lunes 12:00 → martes 12:00 (matriz)
  • Un evento que ocurrió lunes 18:00 en la matriz
  • Debe guardar minuto = minuto_del_lunes_18:00
  • NO minuto = minuto_actual (martes 12:00)
  • Así la GUI muestra la hora correcta del evento

🏗️ Estructura: Clase Mensaje

Ubicación: Scripts/Logica/Mensajes/Mensaje.gd

Tipo: Resource (serializable a .tres)

Propiedad Tipo Significado

descripcion String Detalles ("Te han despedido por falta de higiene")
leido bool false = nuevo | true = ya lo abrió
minuto int Minuto Unix del evento EN LA MATRIZ (crítico)
class_name Mensaje extends Resource @export var titulo: String = "" @export var descripcion: String = "" @export var leido: bool = false @export var minuto: int = 0

💾 Variables Dinámicas

En Variables_Dinamicas.gd:

@export var Mensajes: Array[Mensaje] = []
  • Se inicializa vacío en nueva partida
  • Se guarda/carga automáticamente (binario)
  • Sin límite de mensajes
  • Sin filtros ni categorías (todos juntos)

1. Evento ocurre en la matriz (Futuro)

Ejemplo: cuando se implemente despido de trabajo.

2. Jugador abre botón "Perfil"

En la GUI: Se llama Gestionar_Visibilidad.Visibilizar_Mensajes(raiz)

Se muestra:

  • Título completo
  • Descripción
  • Fecha/hora del evento (convertida desde minuto)

Se marca como leido = true y se guarda.

🎨 UI: Botón Perfil y Pantalla de Mensajes (Estilo Gmail)

Barra inferior (Barra_Abajo), en la posición actual del botón Tienda.

⏰ Conversión de minuto → Fecha/Hora

En Funciones_Globales.gd, crear función:

func Convertir_Minuto_A_Fecha_Hora(minuto: int) -> String: var dia_absoluto = minuto / 1440 var minuto_del_dia = minuto % 1440 var hora = minuto_del_dia / 60 var min_final = minuto_del_dia % 60 var dias_semana = ["Lunes", "Martes", "Miércoles", "Jueves", "Viernes", "Sábado", "Domingo"] var dia_nombre = dias_semana[dia_absoluto % 7] return "%s, %d:%02d" % [dia_nombre, hora, min_final]

Ejemplo:

  • Minuto 1000 → "Lunes, 16:40"
  • Minuto 5000 → "Lunes, 9:40" (siguiente semana, misma hora aprox.)

Caso 4: Evento offline (Crítico)

Escenario

  • Lunes 12:00: Cierras el juego
  • Entre lunes y martes: Ocurren 3 eventos en la matriz:
    • Lunes 18:00 → Despido
    • Martes 08:00 → Necesidad de comida baja
    • Martes 10:00 → Recibiste un bonus (?)
  • Martes 12:00: Abres el juego

Qué debería ocurrir

  • ✓ Sistema procesa lunes 12:00 → martes 12:00
  • ✓ Crea 3 mensajes con minutos originales:
    • Mensaje 1: minuto = minuto_lunes_18:00
    • Mensaje 2: minuto = minuto_martes_08:00
    • Mensaje 3: minuto = minuto_martes_10:00
  • ✓ GUI muestra:
    • "Lunes, 18:00 - Despido"
    • "Martes, 08:00 - ..."
    • "Martes, 10:00 - ..."

Qué NO debería ocurrir

  • ✗ Los 3 mensajes con minuto = martes 12:00 (ejecución actual)
  • Causaría: "¿Por qué me despidieron a las 12:00 si era lunes a las 18:00?"

💾 Persistencia (Save/Load)

Al guardar

En Guardar_Variables_Dinamicas.save_game():

var file = FileAccess.open(path, FileAccess.WRITE) # ... otras variables ... file.store_var(Variables_Dinamicas.Mensajes) # Array[Mensaje]

Nota: Como Mensaje es un Resource, Godot lo serializa automáticamente.

Al cargar

En Guardar_Variables_Dinamicas.load_game():

if file.file_exists(path): var file = FileAccess.open(path, FileAccess.READ) # ... otras variables ... Variables_Dinamicas.Mensajes = file.get_var() else: Variables_Dinamicas.Mensajes = []
